## 1. 一句话定位

**一本会随旅程长出世界的魔法书。** 你像平时一样按天排行程，它把行程变成一座可以走进去的玩具微缩世界（风格化 3D CG，像动画电影里的模型），一个圆润的小人替你从第一站走到最后一站；旅行结束，合上书，它就是这趟旅行的日记。

三个关键词，也是三条不能丢的设计底线：

| 关键词 | 含义 | 不能变成什么 |
|---|---|---|
| **好用的行程工具** | 排行程的效率不能输给圆周旅迹这类专业工具 | 不能为了「像游戏」而让排行程变麻烦 |
| **可以走进去的世界** | 每段旅程是一个按行程生成的玩具微缩世界，小人走站 | 不能只是给列表换个游戏皮肤 |
| **留得下来的日记** | 旅程结束自动沉淀成可导出、可分享的书 | 不能是零散截图 |

## 2. 核心隐喻：一本书，一个世界

整个 App 的导航结构顺着一个隐喻走：

```
书架（我的旅程）
 └── 一本书（一段旅程：目的地 + 日期 + 主题 → 生成一个世界）
      ├── 封面（按世界主题生成，书脊标天数）
      ├── 扉页（序言 + 这趟旅行的世界设定）
      ├── 第 1 页 = 第 1 天（这一天的像素地图 + 行程列表）
      ├── 第 2 页 = 第 2 天
      ├── ...
      └── 封底（旅程统计 + 合上书 → 生成日记）
```

| 现实对象 | 书里的对象 | 在像素世界里的样子 |
|---|---|---|
| 一段旅程 | 一本书 | 一座微缩世界（一块块底板拼成的立体小城；地形、色板、天气、建筑风格随旅程生成） |
| 一天 | 一页 | 一块底板（这一天的区域，带角度看像摆在桌上的模型） |
| 站点（景点/餐厅/商店） | 页上的一个条目 | 一栋用积木搭起来的建筑（系统先搭，用户可改，打卡封顶） |
| 交通 | 两个条目之间的连线 | 小人走路 / 轨道与车辆过场动画 |
| 住宿 | 一页的结尾 | 一栋小屋，小人进门、天黑、翻页 |
| 我 | 书的主人 | 可自定义的像素小人 |
| 旅行结束 | 合上书 | 整座城完成、定格成微缩模型，导出日记 |

**七天长什么样**：`示意图/关西七日_一本书.png` 用一段真实可走的关西七日（大阪 2 天、京都 2 天、奈良 1 天、神户 1 天、大阪返程）验证了这套结构：封面一页，七天各一页，四座城各一块城市尺度的底板；同一座城的两天共用一块底板、换一条路线；跨城的那一天靠交通条目衔接；住宿连住时页脚只写「住 · 京都站前」。行程数据按 8.2 的模型写在 `示例数据/关西七日.json`。

**打开一本书的仪式感**：从书架点开 → 书本翻开动画 → 扉页短暂停留（显示世界名与序言）→ 世界从纸面「长出来」（底板铺开，积木逐块落下）→ 小人出现在第 1 天的起点。这个过场是产品最重要的一个记忆点，值得单独打磨，但要允许二次打开时跳过。

## 3. 目标用户与场景

### 3.1 核心用户

- **自己做攻略的自由行旅行者**，有排行程的习惯，会在出发前反复调整顺序。
- 对**像素/游戏审美**有偏好，玩过或喜欢《星露谷物语》《旅行青蛙》这类作品。
- 旅行后**有记录欲望**，但嫌整理照片和写游记麻烦。

### 3.2 三个使用阶段

| 阶段 | 用户在做什么 | 产品提供什么 |
|---|---|---|
| **出发前** | 收集地点、排顺序、订交通住宿 | 高效的按天编排；像素世界作为「预览」，看一遍行程是否顺 |
| **旅行中** | 看今天去哪、下一站怎么走 | 当天页面 + 小人跟随进度；打卡点亮站点；下一站导航交给系统地图 |
| **旅行后** | 想留个纪念、分享给朋友 | 合上书生成日记；导出长图 / PDF / 回放 |

### 3.3 不是给谁做的

- 只想要「一键生成攻略、别让我动手」的用户（AI 排程可以有，但不是主卖点）。
- 需要团队/商务差旅管理的用户。

## 4. 核心体验流程

```
新建旅程                       打开书                          旅行中                      旅行后
─────────                     ──────                          ──────                      ──────
填目的地/日期/主题 ──► 生成封面与世界 ──► 翻开书 ──► 第 N 页（当天）    ──► 小人跟随进度、打卡  ──► 合上书
        │                                    │           ├─ 编辑视图（列表）         │                      ├─ 日记页自动生成
        │                                    │           └─ 探索视图（像素地图）     │                      └─ 导出 长图/PDF/回放
        └── 可从链接/文本导入站点（P2）       └── 扉页：序言、世界设定            └── 天气/昼夜跟随真实日期
```

**一个主界面，一份数据（判断 D1 → D19 修订）**：

- **探索视图是主界面**：像素微缩世界铺满整屏，小人走站，按天翻页。所有其他东西都悬浮在它上面。
- **编辑视图是悬浮的行程面板**：可展开可收起，卡片列表按天分组，拖拽排序、跨天移动、插入交通 / 住宿都在面板里做，效率对标圆周旅迹。面板与世界联动：点面板里的站，小人走过去；小人到站，面板里的卡片打卡。
- **信息层（判断 D20）**：这仍然是一个攻略 App，地名、交通方式、时间必须一眼看到。地图上每个站点挂「序号 + 计划时间 + 地名」标牌，每段路线中点挂「交通方式 + 时长」标牌，右上常驻「下一站」卡片（站名、交通、时长、预计到达）；非站点地标只留淡的小标签。
- 翻页、镜头、捏人、打卡提示都是浮在世界上的纸片；折叠机上停靠在折痕两侧，手机上行程面板变成底部抽屉。

v0.1 里「编辑视图是书页背面、探索视图是正面」的左右分页做法作废：分割会把世界挤成半屏，游戏感就没了。

### 4.1 从地球进入一天（第四轮，判断 D24–D26）

```
开屏：一颗大地球                 点一本书                        点某一天                      潜入这一天
──────────────                  ──────────                      ──────────                   ──────────
书 = 地球上的一簇路线 + 书签 ──► 镜头飞过去 zoom in ──────► 当天路线高亮 + 当天卡片 ──► 俯冲进「地球上切下来的一块」
底部一排书卡                    书面板：方案切换、统计、序言      站点、每段交通、公里、时长      小人沿真实路形走，底部时间轴
  ├─ 新建：搜一个地方 → 地球转过去 → zoom in → 新书                                           点空白隐藏 UI；🌍 回到地球
  └─ 导入：路径规划页 / JSON → 一页两个方案 = 同组两本书
```

- **地球是首页，也是目录**：所有书都在同一颗地球上，旅行中的书标「旅行中 · 今天 D6」，未出发的标「还有 N 天」。
- **书面板替代扉页**：同组的几个方案并排切换，统计（天、站、公里、自驾时长）与序言在面板里。
- **一天 = 一块漂浮的地**：真实目的地按当天站点的经纬度切一块，海岸线、路形、地形都来自真实数据；手画底板只留给已有底板的城市。
- **画面 = 平面插画的天空 + 3D 渲染的地与人**：天空、纸片云、漂浮小岛是插画层，3D 只画地球、当天那块地、小人和地标。

## 5. 功能模块

### 5.1 行程编排（旅程 → 天 → 条目）

**层级**

```
Trip（旅程）
 └── Day（天，按日期顺序）
      └── Entry（条目，有序）
           ├── Place     站点：景点 / 餐饮 / 购物 / 自定义
           ├── Transport 交通：连接前后两个站点
           └── Lodging   住宿：一天的终点
```

**三类条目的规则（判断 D3）**

| 条目 | 位置规则 | 关键字段 | 备注 |
|---|---|---|---|
| 站点 Place | 任意位置，可拖拽 | 名称、类别、坐标、计划时段、费用、备注、图片 | 类别决定像素世界里的建筑 tile |
| 交通 Transport | 只能插在两个站点之间（或一天的开头/结尾） | 方式（步行/地铁/公交/打车/高铁/飞机/轮渡/自驾）、时长、费用、票务截图 | 删除相邻站点时提示如何处理这段交通 |
| 住宿 Lodging | 默认在一天末尾；同一住宿连续多晚自动延续到后面几天 | 名称、入住/退房日期、坐标、费用、预订号 | 像素世界里小人「进门 → 天黑 → 翻页」 |

**编辑操作**

- 添加站点：搜索 POI（接系统地图 SDK）/ 手动输入 / 从收藏夹拖入。
- 拖拽排序；长按跨天移动；一键「把这一站挪到明天开头」。
- 每一天可选填「今日主题」（例如「老城区 · 徒步日」），会成为像素世界这一页的标题。
- 时间可选：不填时间也能排（很多人只排顺序不排时间）。
- 费用汇总：按天、按类别自动加总（对齐圆周旅迹 2026 年 9 月新增的记账能力，但我们做轻量版）。

**示例数据**：`示例数据/关西七日.json` 是一段完整的七天行程，23 个站点、25 段交通、3 家住宿，可以直接作为黄金用例的输入（技术选型 4.4）。

**导入（P2）**：粘贴小红书 / 公众号 / 文本 → AI 解析出站点列表 → 用户确认后落到某一天。这是圆周旅迹的核心卖点，我们后做，做时要复用它已经教育好的用户习惯。

### 5.2 微缩世界（探索视图，v0.3：风格化 3D CG）

**这是产品的差异点，也是最难做对的部分。** 定义如下。

**视角（v0.2 新增）**

- 不是纯俯视，是**带角度的游戏视角**：正交相机，默认俯仰 26.6°（2:1 二等角，像素等距游戏的标准角，见附录 A）、方位 45°，像一座摆在桌上的微缩模型。
- 视角有档位，不自由飞：俯仰两档（90° 俯视用于「看全天」，约 30° 用于「看世界」），方位四档（每次转 90°，双指旋转后吸附）。CG 下可以带一点透视（视场角约 20°），更像摆在桌上的模型；档位仍保留，保证用户不会迷失。
- 质感来自三处：圆润的积木造型（轻微倒角）、绘画质感的贴图、动画电影式的光影与移轴景深。**不做像素化**，按屏幕原生分辨率渲染；《潜水员戴夫》新画风、LEGO Builder's Journey 是参照。
- 在折叠屏跨页右页和悬停态上半屏里，这个「桌上模型」的感觉最强（第 7 节）。
- 带角度到底好不好、为什么是这个角度、参考哪些像素游戏，见附录 A。

**尺度（第二轮追问后修订）**

- **主视图是城市尺度，不是街区尺度。** 一天的行程通常横跨整座城（京都一日：车站到金阁寺直线约 8 公里），底板要把这一天去的地方全放进去。一格约 100–300 米，按当天站点的外接框自适应；44 × 30 格能放下京都核心区。示意图见 `示意图/城市尺度_京都一日.png`。
- **地标放大，街区只画肌理。** 学旅游手绘地图的做法：站点建筑按 2–4 格的尺寸夸张，远大于真实占地；普通街区不画楼，只铺一层浅色底板加零星小砖表示密度；山、河、主干道、铁路、地铁线是骨架，一眼认出是哪座城靠的是骨架，不是楼。
- **距离压缩。** 站点之间的空白段按比例压缩、保持相对方位（北在上），避免半块底板是空的。
- **两级尺度。** 城市尺度是看行程的视图；点开某个站点进入单体尺度（那栋积木建筑放大到整屏），搭建模式（5.6）在单体尺度里进行。街区尺度（一格几十米、一栋栋房子，即 `示意图/视角对比.png` 那种）不做主视图：它既不是攻略的粒度，也超出生成与性能预算。

**空间组织**

- **一天一块底板**。每天是一个「关卡」，底板之间由交通过场连接（走出底板边缘 → 交通动画 → 进入下一块）。
- 底板上的山、河、主干道、铁路、绿地与街区肌理：**由真实地图数据（OpenStreetMap）自动生成**，服务端把该区域栅格化成分类网格，再按地形主题的规则自动铺积木模块；站点换成放大的地标模板，方案见 `03_地图生成与渲染方案.md`。这样地图有「真的是这个城市」的感觉，又不需要真实地图底图，也不用逐个城市手搭。
- 兜底：地图数据稀疏的地区退化为「抽象布局」，站点按真实经纬度归一化到网格、保持相对方位，由生成器补一条主路连起来。
- 站点吸附到最近的道路格；站点本身是一栋积木建筑（5.6）；若一天的站点跨度极大（如跨城），自动拆成两块底板。
- 起点：当天第一个站点，或前一晚住宿。终点：当晚住宿，或最后一个站点。

**小人与行走**

- 小人沿格子路径从站点 A 走到 B；路径由简单寻路（A*）在可走格上生成。
- 交通方式决定过渡：步行 = 正常走；地铁/公交 = 进站 → 黑屏字幕「地铁 · 18 分钟」→ 出站；高铁/飞机 = 全屏过场（车窗/舷窗动画）+ 翻页。
- 到达站点：小人停在门口，建筑封顶（5.6）并亮起，弹出该站点的卡片（名称、计划时段、备注、照片）。

**播放控制**

- 自动播放整天（可调速）；点任一站点直接跳转；底部进度条与编辑视图的条目一一对应。
- 旅行中（真实日期落在旅程内）：小人的默认位置 = 当前已打卡的最后一站；用户到达后点「已到达」→ 打卡 → 建筑封顶并记录时间。

**世界氛围**

- 昼夜：按站点计划时段 / 真实时间切换白天、黄昏、夜晚色调；3D 下有真实的影子，影子方向随时段转。
- 天气：出发前按目的地气候档案随机；旅行中接真实天气（P1）。
- NPC：少量固定 NPC（店主、路人）带一两句台词，台词由世界设定生成（P1）。

**性能预算（用于技术选型）**

- 单块底板 ≤ 64×64 格（城市尺度，一格 100–300 米），高度 ≤ 16 层积木；积木合并网格后 ≤ 20 万三角形。
- 同屏动态角色 ≤ 20 个。
- 屏幕原生分辨率渲染，后处理（景深、bloom、SSAO）按机型分档开关；目标 60 fps，中端机不掉帧；切换底板 ≤ 500 ms。

### 5.3 世界生成（每本书不一样）

**输入**：目的地（国家/城市）、日期（→ 季节）、旅行主题（美食 / 自然 / 城市漫游 / 亲子 / 蜜月 / 徒步…）、天数、站点类别分布。

**输出**：一份 `WorldSpec`（世界规格），驱动封面、扉页、每页地图和日记模板。它分两半：**风格**（`style`：地形主题、色板、tileset、文案）由本节的规则表 + 种子生成；**几何**（`mapRef`：每天区域的路、河、建筑块）由真实地图数据生成，见 `03_地图生成与渲染方案.md`。

| 生成项 | 生成方式 | 举例 |
|---|---|---|
| 地形主题（biome） | 查表：目的地 → 候选主题 → 按季节修正 | 京都·秋 → 「红叶古都」；冲绳·夏 → 「海岛」；北欧·冬 → 「雪国」 |
| 色板 | 每个主题 2–3 套，由种子选择 | 红叶古都：朱红 / 深褐 / 米白 |
| 建筑风格 | 主题 → tileset 变体；站点类别 → 具体建筑 | 「餐饮」在古都是町屋食堂，在海岛是海边小屋 |
| 天气档案 | 目的地气候 + 季节 | 雨季概率、日落时间 |
| 书名 / 序言 / 每日标题 | AI 生成文字（可编辑、可关闭） | 「第三日 · 沿鸭川向北」 |
| NPC 与台词 | 主题模板 + AI 填词（P1） | 店主：「这个季节的栗子最好。」 |

**判断 D4 的落地**：

- 同一段旅程的 `seed` 固定，世界每次打开都一样；用户可以手动「重掷」一次换风格。
- 规则表是产品资产，应当以数据文件（JSON）维护，跨端共用，设计师可以直接改。
- AI 只做文字，不做图像生成：像素素材由人绘制并组织成 tileset，保证风格统一与离线可用。

### 5.4 旅行日记与导出

**日记从哪来**

- 自动：行程结构、打卡时间、交通里程、站点数、天数、花费汇总。
- 用户：每个站点的照片与一句话感受；每一天的日记正文（可在旅行中随手写）。
- 世界：封面、每页的像素地图截图、小人走完全程的路径。

**导出形式**

| 形式 | 场景 | 阶段 |
|---|---|---|
| 像素长图（每天一段 + 结尾统计） | 分享到社交 | P0 |
| PDF 书册（封面 + 扉页 + 每天一页 + 封底） | 打印 / 留存 | P1 |
| 单站点卡片图 | 发一条朋友圈 | P1 |
| 微缩世界定角度渲染图（俯拍 / 斜拍） | 封面与每页插图 | P0 |
| 可旋转的 3D 微缩模型（glTF，配合系统 AR 快速查看） | 把这趟旅行摆在桌上 | P3 |
| 小人走完全程的回放（GIF / 短视频） | 分享 | P3 |
| 结构化数据（JSON / iCal） | 迁移到其它工具 | P2 |

导出模板本身也遵循魔法书风格，不同世界主题有不同的纸张纹理与边框。

### 5.5 游戏化机制（判断 D6）

做的：

- **收集**：站点打卡得贴纸；按城市形成图鉴；同一城市多次旅行的贴纸会累积。
- **成就**：首次出国、连续 N 天、夜猫子（夜间站点 ≥ 3）、美食家（餐饮站点 ≥ 10）等。
- **小人成长**：服装、道具、宠物随旅行解锁；解锁靠「真实旅行里程」而非「打开 App 次数」。
- **书架**：书越多，书架越丰富（书架背景与摆件由旅程数解锁）。

不做的：

- 排行榜、好友对比。
- 每日签到、断签惩罚。
- 用付费购买成就。

原则：所有游戏化奖励都要能反向解释为「这趟旅行留下了什么」。

### 5.6 搭建模式：站点像积木一样搭起来（v0.2 新增）

**每个站点是一栋积木建筑（Build）。** 它由三层叠出来：

| 来源 | 内容 | 谁做 |
|---|---|---|
| 地图数据 | 底座形状（OSM 建筑轮廓）、高度（层数） | 生成器自动 |
| 类别模板 | 寺庙、餐馆、车站、公园、博物馆……每类几套积木模板，按地形主题换配色和屋顶 | 设计师配，生成器按种子选 |
| 用户搭建 | 在搭建模式里换色、改砖、加装饰（招牌、灯笼、树、长椅），或推倒重来 | 用户，可选 |

**搭建规则**

- 积木单位与地图格对齐：1 格 = 1 块基础砖的底面，高度以「层」计，所有砖都在网格上。
- 砖的种类有限（基础方块、斜面、圆柱、板、装饰件），颜色来自当前世界的色板。限制是为了风格统一，也让搭建像玩具而不是建模软件。
- 默认模板就是「说明书」，用户可以照着搭、也可以改；改坏了一键回到模板。
- **打卡 = 封顶**：到达站点时放上最后一块砖（屋顶或旗帜）。未打卡的建筑保持「未完成」状态（缺顶、带脚手架），旅行结束时整座城完成。这是打卡行为在世界里的物理反馈，比「点亮」更有分量。
- 交通是轨道 / 道路件，住宿是小屋模板，小人是这座城里唯一会动的东西。

**在编辑视图里的对应**：条目卡片本身就画成积木块，按天叠成一摞；同一块积木在探索视图里就是那栋建筑。两种视图共用一个隐喻，拖动卡片就是挪积木。

**与游戏化的关系**：新的砖、装饰件、模板通过旅行解锁（5.5）；主题积木包是变现候选（Q5）。

**边界**

- 不做自由建模：不允许任意尺寸的砖，不允许脱离网格。
- 搭建是可选的：从不打开搭建模式的用户，也能得到一座完整的、由模板生成的城。
- 商标与外观：产品内不使用「乐高 / LEGO」字样，小人不做成乐高人仔的造型，砖的凸点与比例采用自己的设计；上线前法务过一遍（Q15）。

### 5.7 卡通小人：形象、自定义、在路线上走（v0.3 改为 3D 卡通模型）

**气质**：参照《潜水员戴夫》新画风里的角色：比例夸张（大头、宽厚的身体、短腿）、表情丰富（眼白与瞳孔、眉毛、张嘴笑）、皮肤红润、布料有体积，像动画电影里走出来的人。像素时期的设定见 `示意图/像素小人_设定图.png`，槽位沿用；CG 版小人见 `示意图/画风对比_像素_vs_3DCG.png` 右下与原型的 CG 模式（原型里的只是矢量近似）。不复制任何现有 IP 的造型。

**默认形象**：女性旅行者，双丸子加长侧发、齐刘海、草帽配珊瑚缎带、浅青连衣裙、小挎包、玛丽珍鞋（`示意图/blender/blender_hero_post.png`）。捏人槽位仍开放，男女由发型与服装表达。

**规格**

| 项目 | 约定 |
|---|---|
| 形态 | 3D 卡通模型，头身比约 1 : 2.5，身体宽厚、四肢短圆，无描边，绘画质感材质；一个基础模型，模块化部件换装 |
| 方向 | 真 3D，随移动方向转身；相机档位切换时平滑转向 |
| 动作 | 骨骼动画 + 表情：走、跑（坐车前后）、待机（眨眼、左右看）、打卡（举手 + 张嘴笑 + 一次挤压拉伸的小跳）、坐车（只露上半身）；表情做 4 个：平静、开心、惊讶、疲惫 |
| 部件 | 头发、帽子、上衣、下装、鞋、配件各为独立网格；颜色是材质参数，不出多套贴图 |
| 节奏 | 走路步进感保留（动画曲线偏卡通），镜头与面板平滑 |

**自定义槽位（P0 的最小集合）**

| 槽位 | 数量 | 说明 |
|---|---|---|
| 肤色 | 5 | |
| 发型 × 发色 | 4 × 7 | 短发、长发、双丸子、卷发 |
| 上衣 / 下装 / 鞋 | 8 / 6 / 3 色 | 网格固定，先只换材质色 |
| 帽子 | 3 款 × 5 色 | 棒球帽、毛线帽、草帽 |
| 配件 | 4 | 眼镜、围巾、相机、背包（背面与侧面可见） |

新款式通过旅行解锁（5.5）：去过海边解锁草帽，坐过火车解锁列车长帽，冬天旅行解锁围巾。槽位数量刻意少：像素小人的辨识度来自剪影，槽位一多就成了换装游戏。

**在路线上走**：小人沿路径格逐格移动，方向跟随移动方向切换四向精灵；步行段两帧一格，坐车段一帧一格并换成车辆精灵（小人只露上半身）；到站停下、面向镜头、举手打卡，建筑封顶（5.6）。镜头跟随小人，带一点缓动。这套规则就是 GIF 里演示的那套。

**边界**：不做脸型与体型自定义（保持一个剪影，这是成本与辨识度的双重原因），不做自由捏脸，性别不作为槽位（用发型、服装表达）。

## 6. 视觉规范（v0.3：风格化 3D CG，参照《潜水员戴夫》新画风）

> v0.1 / v0.2 的像素规范作废，保留在附录 A 与 `04_视觉风格_近年像素.md` 里作为对照。
> 参照物是《潜水员戴夫》换画风之后的宣传图：饱和而和谐的电影色（蓝绿的海天配暖橙的皮肤与金色标题），强主光加明显的轮廓光，布料、毛发、皮肤有体积和纹理，角色比例夸张、表情丰富，背景是绘画笔触的云、岩、植被。一句话：**动画电影的质感，不是治愈系粉彩，也不是低多边形。**

| 项目 | 约定 | 说明 |
|---|---|---|
| 世界造型 | 积木微缩模型：方块、斜面、圆柱、板、装饰件，边缘轻微倒角 | 玩具感来自倒角与圆润，不来自像素 |
| 材质 | 绘画质感贴图（可见笔触 + 微噪点），布料有织纹、木石有肌理，无描边 | 《潜水员戴夫》新画风的材质密度；LEGO Builder's Journey 的塑料感只作倒角与反光参考 |
| 色板 | **饱和而和谐的电影色**：主色对（蓝绿 × 暖橙），高光偏暖、阴影偏蓝，无纯黑纯白；每个世界主题一套主题色（红叶古都、海岛、雪国……） | 04 第 4 节的「降饱和粉彩」按此修正 |
| 整体色调 | **默认「清朗海天」**：天蓝背景、青绿水面、鲜绿植被、白色路网、珊瑚橙点缀，UI 冷白卡片，封面海蓝配金黄标题（参照《潜水员戴夫》新画风的海天）。备选「暖阳纸张」（原来的暖黄调，已弃用为默认）、「暮色琥珀」（黄昏，用于夜景与回顾页）。示意见 `示意图/色调对比.png` | 仓库主人第三轮反馈「不喜欢暖黄调」后改定 |
| 光照 | 强主光 + 天光 + **轮廓光**（角色与地标有明显的亮边）；软阴影；环境光遮蔽；日夜四档，夜里灯窗自发光 | 影子方向随时段转；轮廓光是「电影感」的关键 |
| 后期 | 移轴景深、暗角、电影感分级（高光偏暖、阴影偏蓝、对比略高）、轻微胶片颗粒、bloom、粒子（主题：红叶 / 海鸟 / 雪） | 按机型分档，中端机可关 bloom 与 SSAO |
| 相机 | 轻透视（视场角约 20°），俯仰约 30° / 90° 两档，方位四档 | 档位保留，见 5.2 |
| 角色 | 3D 卡通模型，比例夸张（大头、宽厚的身体、短腿），**表情丰富**（有眼白与瞳孔、眉毛、嘴，笑起来露齿），无描边 | 见 5.7；像素时期的「两点眼」不再是约束 |
| UI | 半透明白卡片 + 背景模糊 + 柔和阴影 + 12–14 px 圆角，无描边 | 攻略信息层可读性优先（D20） |
| 字体 | 系统字体（HarmonyOS Sans / 苹方） | 点阵字体只在贴纸、徽章、章印这类彩蛋处用 |
| 动效 | 镜头、面板、粒子、光照平滑；角色动画曲线偏卡通（挤压拉伸） | 走路的「步进感」用动画曲线做，不用低帧率 |
| 深色模式 | 夜晚光照 + 深色半透明卡片 | 不另做一套灰色 UI |

**像素的位置**：打卡贴纸、成就徽章、日记章印保留像素风，作为「游戏感」的彩蛋与品牌记忆点；世界和角色不再像素化。

素材来源策略：积木库、贴图、角色全部自制（保证风格统一与版权干净）；原型阶段的近似渲染（`示意图/render_cg.py`）只用于沟通，不进产品。

## 7. 折叠屏与大屏场景

> 第一次讨论中补充的要求：多考虑折叠屏场景，重点是华为 Pura X Max 与苹果 iPhone Duo。

### 7.1 两台目标机型的形态

| 机型 | 外屏（合上） | 内屏（展开） | 开合方式 | 备注 |
|---|---|---|---|---|
| 华为 Pura X Max | 5.4 英寸，1848×1264，约 √2:1，竖持像一页纸 | 7.7 英寸，2584×1828，约 √2:1，摊开像一本打开的书 | 左右开合（书式） | 内外屏都是「阔」比例，官方叫阔折叠；√2:1 正是 ISO 纸张的比例 |
| Apple iPhone Duo | 5.4 英寸，1398×2034，比常规手机略宽 | 7.6 英寸，2670×1878，约 √2:1 | 左右开合（书式） | 支持 Apple Pencil；内屏屏下摄像头；2026 年 9 月发布，10 月上市 |

两台机器展开后都接近 √2:1 的横向画幅：**合上是一页，展开是一个跨页。** 这和产品的「书」隐喻是同一件事，折叠屏不是需要适配的麻烦，而是这个产品最合适的载体。

### 7.2 设计原则：开合手机 = 开合这本书

| 设备状态 | 书的状态 | 界面 |
|---|---|---|
| 合上（外屏） | 书合着，只露出一页 | 计划期：书架与封面；旅行中：今天这一页（日期、今日主题、站点列表、下一站） |
| 展开（内屏，横持） | 书摊开成跨页 | 微缩世界铺满整个跨页；行程面板等纸片悬浮停靠在折痕两侧，不跨折痕；书脊只是世界上的一道光影 |
| 半开悬停（约 90°，横放桌面） | 书立在桌上 | 上半屏像素地图，下半屏时间轴 / 控制 / 日记键盘；旅行中放在咖啡桌上就是一个立体小景 |
| 展开后竖持 | 单页放大 | 单视图全屏（像素地图或列表），适合躺着看 |

关键规则：

- **内外屏接续**：合上时看的是哪一天，展开就摊开到那一天；展开时停在哪一站，合上后外屏就显示那一站。
- **铰链就是书脊**：两页之间的留白对齐到折痕区域；任何可点击元素、任何 tile 都不跨折痕；像素地图的 tile 网格从折痕向两侧铺，折痕线落在 tile 边界上。
- **面板与世界联动**：面板里选中一个条目，小人走到那一站；世界里点一栋建筑，面板滚到对应卡片。展开态下世界大、面板也能常驻展开，两者同时在眼前。
- **不为折叠屏单独做一套页面**：同一套页面在不同断点下改布局（鸿蒙「一次开发，多端部署」的断点体系；iOS 用 size class）。

### 7.3 微缩世界在不同屏幕上的画面（v0.3）

| 屏幕 | 后处理档位 | 默认视角 | 镜头策略 |
|---|---|---|---|
| 常规手机（竖持） | 中：景深 + 暗角，关 SSAO | 俯仰约 30° | 镜头跟随小人 |
| Pura X Max 外屏（竖持） | 中 | 俯仰约 30° | 跟随小人，上方留时间轴 |
| Pura X Max / iPhone Duo 内屏（展开） | 高：全开 | 俯仰约 30°，可切 90° 看全天 | 世界铺满跨页，镜头跟随小人；「全景」时整块底板入画 |
| 悬停态上半屏 | 高 | 俯仰约 30°，双指旋转四档 | 全景，像桌上的模型 |

原生分辨率渲染；折痕落在世界上只是一道光影，悬浮面板停靠在折痕两侧（第 4 节）。

### 7.4 折叠屏独有的功能机会

- **Apple Pencil 手写日记**（iPhone Duo）：日记页支持手写与涂鸦，导出 PDF 时保留笔迹；Pura X Max 是否支持手写笔待核实。
- **悬停立体小景**：旅行中把手机半开立在桌上，上半屏以 26.6° 视角缓慢环绕今天的底板，作为氛围展示，不需要任何操作。3D 视角让这个场景成立。
- **跨页导出即所见**：展开态的跨页布局就是 PDF 书册的版式，展开态本身就是导出的预览。
- **分屏协作**：内屏上本 App 与系统地图并排，左边看行程、右边导航（鸿蒙分屏；iOS 侧的多任务能力以 iPhone Duo 实机为准）。
- **外屏作为行程卡**：旅行中外屏显示下一站与出发时间（鸿蒙实况窗；iOS 全天候显示的可用能力待核实）。

### 7.5 阶段安排

- **P0**：手机竖屏 + 折叠屏展开态双页。鸿蒙首发机型里 Pura X Max 是旗舰，一多适配从第一天做，不留到后面补。
- **P1**：外屏页、悬停态、折痕避让打磨、iPhone Duo 适配与 Pencil 手写。
- **P2 及以后**：分屏协作、悬停立体小景动效。

## 8. 信息架构与数据模型草案

### 8.1 页面结构

```
书架 Shelf
 ├── 新建旅程 NewTrip（目的地 / 日期 / 主题 → 预览封面）
 ├── 设置 Settings（小人形象、图鉴、成就、导出记录）
 └── 一本书 Book
      ├── 扉页 Prologue
      ├── 某一天 DayPage
      │    ├── 编辑视图 EditView（列表）
      │    ├── 探索视图 ExploreView（微缩世界）
      │    └── 搭建模式 BuildView（从探索视图里某栋建筑进入，P1）
      ├── 站点详情 EntryDetail（两种视图共用）
      └── 封底 Epilogue（统计 / 合上书 / 导出）
```

### 8.2 数据模型（与平台无关）


约定：

- 交通的 `from/to` 指向站点或住宿，删除任一端时交通进入「悬空」状态并提示用户。
- `WorldSpec` 与行程分离存储：改行程不会改世界；只有用户主动「重掷」才重新生成。
- `Build.bricks` 默认由模板 + 底座生成，不落库；用户改过（`userEdited`）才整份落库，回到模板即删除。
- `WorldSpec.mapRef` 指向每天一块底板的数据（地面模块网格 + 高度图 + 建筑块列表），由服务端生成并缓存。
- 所有坐标只用于像素世界布局和跳转到系统地图，不做路径导航。

## 9. 与圆周旅迹的对照

> 核实：讨论中提到的「圆周旅记」，官方名称为**圆周旅迹（Pi Travel）**，iOS / 安卓 / 微信小程序均有，官网 pitravel.cn。本节基于公开介绍整理，具体交互细节需要实际安装对照。

| 维度 | 圆周旅迹的做法 | 我们的取舍 |
|---|---|---|
| 行程结构 | 按天排列的地点卡片，可拖拽优化动线 | **借鉴**：同样的天 → 卡片结构，拖拽排序 |
| 交通 | 站点之间显示移动耗时，接实时交通数据 | **借鉴并扩展**：交通是显式条目，可以带票务与费用；耗时估算 P1 |
| 住宿 | 作为地点加入行程 | **改**：住宿是一天的「归宿」，多晚自动延续，驱动翻页动画 |
| 地图模式 | 真实地图 + 3D 地标 | **不做真实地图模式**：像素世界替代；真实导航跳转系统地图 |
| 复制攻略 | 一键解析小红书 / 公众号链接成行程（核心卖点） | P2 跟进，不作为主卖点 |
| AI 智能规划 | 按天气、人流动态调整 | 不做；我们的 AI 只写文字 |
| 多人协作 | 实时协作 | P2 |
| 记账 | 2026 年 9 月新增 | 轻量费用汇总，P0 只做加总 |
| 视觉 | 简约扁平 | 像素魔法书，完全不同的定位 |
| 出行后 | 路线记录 | **强项**：日记与导出是我们的闭环 |

结论：圆周旅迹是「排行程」这件事的效率标杆，我们在编辑视图上对标它的效率下限；差异化全部押在「世界」和「日记」上。

## 附录 A · 视角判断：带角度好不好，参考哪些像素游戏

> v0.3 起画风已定为风格化 3D CG，本附录关于「像素等距 26.6°」「像素精灵」的结论不再约束，视角档位的结论仍然有效。保留作为决策记录。

> 第二轮追问：这样显示好不好？游戏视图通常都有一个辅助式的固定角度，参考一些像素游戏。

### A.1 像素游戏的角度都是「作弊」出来的

| 视角 | 代表作 | 怎么作弊 | 能旋转吗 |
|---|---|---|---|
| 3/4 俯视 | 星露谷物语、宝可梦（GBA 时期）、塞尔达传说：众神的三角力量、Undertale、Eastward | 地面是正俯视，物体却画出正面：同时看到屋顶和门脸，现实中不可能，但最易读 | 不能 |
| 2:1 像素等距（二等角） | 模拟城市 2000、过山车大亨、暗黑破坏神 II、辐射 1/2、Into the Breach、Songs of Conquest | 斜线按「横走 2 格、竖进 1 格」画，俯仰角其实是 26.6°，不是真等距的 30°，为的是像素斜线干净不出锯齿 | 通常不能，或预渲染 4 个方向 |
| HD-2D | 歧路旅人、三角战略、勇者斗恶龙 III HD-2D | 3D 场景 + 像素精灵人物 + 移轴景深，相机固定斜角 | 基本不能，个别场景小幅转 |
| 体素固定角 | 天天过马路（Crossy Road）、Stonehearth、Cloud Gardens | 3D 体素 + 像素纹理，相机固定二等角；Stonehearth 允许 4 方向旋转 | 4 档 |
| 体素自由视角 | 我的世界 | 全 3D，只有纹理是像素 | 自由 |
| 3D 搭建小景（非像素） | Townscaper、Tiny Glade | 点一下长一块，相机可环绕；搭建手感的标杆 | 自由 |

规律：**越像「像素画」，角度越固定；越能旋转，越像「3D 模型」。** 像素游戏都用一个固定的辅助角度，是因为画面是画出来的，画师控制每一个像素的可读性；角度一动，作弊就穿帮。

### A.2 判断

带角度显示，**好，但只有在「固定辅助角度」的前提下才好。** 具体四条：

1. **主视角定为 2:1 二等角**：俯仰 26.6°、方位 45°，正交投影。这是像素等距游戏几十年验证过的角度：屋顶、正面、侧面三面可见，斜线在像素网格上走 2:1 台阶，干净。用 3D 引擎做这件事，得到的是「模拟城市 2000 的画面」加上「可以旋转和搭建的自由」。
2. **旋转只给 4 个方位档加 1 个正俯视档，不给连续旋转。** 连续旋转之下像素纹理出摩尔纹、边缘闪、像素密度感散掉，它就不再像像素画，而像一个低清 3D 模型。Stonehearth 是「4 档旋转 + 像素体素」能成立的证据；天天过马路是「一个固定角 + 体素」能很可爱的证据。
3. **人物用面向相机的像素精灵，建筑用像素纹理的体素积木。** 这是 HD-2D 的配方。人物是玩家最盯着看的东西，手绘精灵比体素小人更有像素画的灵气，也便宜；建筑是可搭的，必须是体素。
4. **保留 3/4 俯视作为对照。** P0 原型阶段用同一块底板出两张图：3/4 俯视（星露谷式）与 26.6° 二等角（积木式），并排给目标用户看。如果 3/4 俯视的「像素画」辨识度明显更高，退回 v0.1 的 2D 方案（技术选型第 11 节已留退路）。

### A.3 要认的代价

- **审美偏移**：第一轮说的参考是星露谷（手绘 3/4），第二轮说的是积木。这是两种不同的像素审美，不能都要。选积木，就要接受「天天过马路 / Stonehearth」这一路的体素味，而不是星露谷的手绘味。
- **成本**：3D 资源管线（体素建模、glTF、引擎）比 2D tile 重，团队要有一个会引擎的人。
- **遮挡**：二等角下前排建筑会挡后排。要有处理：点击某栋时前排建筑半透明，或整块底板可切到正俯视档看全貌。模拟城市系列和 HD-2D 都这么做。
- **像素密度**：正交投影下远近物体像素大小一致，这是好事；但低分辨率渲染目标的档位要按屏幕固定（7.3），否则同一块砖在外屏和内屏上像素粗细不同，像素感就散了。
| Q16 | CG 质感的验收：什么样算「精致」而不是「廉价手游」 | 引擎里出一块真实光照的底板 + 一个卡通小人（S16），并排《潜水员戴夫》截图评审 | 仓库主人 + 美术 |
