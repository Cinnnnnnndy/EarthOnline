# 07 设计交接：把「地球Online」交给 Claude Design 做一次整体校准

> 编写日期：2026-10-03（第八轮末）。这一份是给 Claude Design（claude.ai 里的设计画布）用的交接包：产品是什么、哪些规则不能动、令牌是什么、组件长什么样、四个关键屏现在的样子与已知问题、3D 建模部分要什么、请回给我们什么。读者是 Claude Design 本身，也可以是任何接手视觉的人。
> 代码里的真相以 `app/shared/world/tokens.ts`、`app/web/src/app.css`、`app/ios/EarthOnline/Design/*.swift` 为准；这里是它们的人话版。

## 0. 怎么用 Claude Design 过这一遍

1. 在 claude.ai 打开 Design，新建一个设计项目，把本文件整个贴进去（或作为附件），再把第 5 节、第 6 节列出的截图一起拖进去。
2. 第一句话先让它**按第 3 节建一套 Design System**（色、字、间距、圆角、玻璃、图标），之后所有画板都挂在这套系统上。不要让它自己发明新的强调色。
3. 然后按第 5 节一屏一屏来：每屏先给它「现状截图 + 已知问题」，让它出 390 × 844 的画板，白天、夜里各一张。要求它只用两档字号、三种按钮、一种标签，理由见第 2 节。
4. 3D 建模部分（第 6 节）Claude Design 做不了几何，但能做三样东西：风格板（style frames）、比例与配色表、对现有模型截图的逐个批注。拿到这些，我们在代码（`landmark-kit.ts`、`landmarks/*.ts`、`hero-*.ts`）里改。
5. 它回的画板按第 7 节的格式交回来，我们对照着改网页与 iOS，改完再截图回去对一遍。

如果想省第 2 步，这个会话可以直接从令牌表生成一份 Design System 工件（claude.ai 的「Design System」类型），说一声就建。

## 1. 产品一句话

**地球Online**：把旅行计划做成一本放在地球上的书。开屏是一颗可转的地球，每一趟旅程是地球上的一本书，翻开书是一天一天，潜进某一天是一块漂浮的地，小人在上面按行程走。规划（新建、语音、导入、待办）、旅行中（打卡、导航）、旅行后（日记、足迹）都在这一个世界里。

受众：会自己做攻略、也想留下点东西的个人旅行者；中文为主，英文、日文齐备。平台：网页参考应用（Vite + TypeScript + three.js）、iOS（SwiftUI，iOS 26 液态玻璃）、鸿蒙（待做）。

这一包要的不是重新设计，是**校准**：把八轮迭代下来的界面收到一套干净、克制、系统 App 气质的视觉里，再把 3D 的名胜模型统一到同一个比例与色板。

## 2. 不能动的规则（八轮讨论定下来的判断，压缩版）

- **世界是主角，界面让路。** 地球、浮岛、小人占满屏幕；界面只有悬浮的玻璃元素和底部一张贴内容高度的抽屉。没有标签栏、没有汉堡菜单。
- **强调色已去色。** 能点的、选中的、路线一律墨色（夜里白）。全应用只有一个带颜色的按钮：「新建旅程」，蜜 → 晨 → 琥珀的暖胶囊。
- **高亮色只有一个「晨」**：现在（今天、旅行中）与去过（足迹旗、打过卡）。
- **按钮只有三种**：墨色小胶囊（主）、玻璃小胶囊（次）、文字按钮；通用操作（编辑、删除、清除、重写、导入、导出、勾选）一律图标按钮，32 的圆，点击区 44，带读屏标签。
- **同一类信息用同一种标签**：12 → 13 号半粗、高 20 的小胶囊；浅填充次墨字，「现在」用晨色。一行里标签不超过两个；标签不做按钮。
- **字号只有两档**：17 与 13（判断 D69，调研见视觉文档 15.11）。标题也是 17 粗；层级靠字重（600 / 400）与颜色（墨 / 墨·次 / 雾），不靠字号。不用字间距、不用全大写、不用「A · B · C」的中点串。
- **弹层只有四样东西**：标题、一两行列表、一个输入框、一排小按钮。站点详情里待办、备注都是入口行，点进去再看。
- **行程从上往下有顺序**：站点行左边是墨底白字的序号，一条细线串起来，组图标在名字前；交通是缩进的一行。
- **行程列表的图标**：交通一种、住宿一种、其余按六组（人文 / 自然 / 休闲 / 吃喝购物 / 交通 / 住宿）。
- **对比度算到玻璃上**：文字对「玻璃叠在海面上」的底 ≥ 4.5（15.9 的表）。焦点环墨色 2px。
- **动效**：非用户触发的只有新建按钮那一道流光；其余动效都是回应操作的。尊重「减弱动态效果」。
- **文案**：句子，不是标签；按钮说清楚会发生什么；三种语言同一张表。

### 3.2 字

- 字体：苹果用系统字体（苹方 + SF Pro），鸿蒙用 HarmonyOS Sans，其他设备用随包的 HarmonyOS Sans SC。
- 两档：**17 / 22**（正文、标题用 600、按钮用 600）与 **13 / 18**（次要、标签用 600）。
- 颜色三级：墨、墨·次、雾。数字用等宽数字（tabular）。

### 3.3 间距、圆角、尺寸

- 间距只用 **4 / 8 / 12 / 16 / 24**：行的左缩进 16，右 12；图标到文字 12；行内图标到文字 8；标签之间 4；卡片内距 16；屏幕边距 16。
- 圆角：小 10、中 14、大 22、抽屉 26、胶囊 999。
- 行高 ≥ 52（两行 56）；按钮 36（点击区外扩到 44）；图标按钮 32 / 44；标签 20；序号圆 22；新建旅程 44。
- 图标：描边 1.8，24 网格；行首 16，行内 14，按钮里 16～18。iOS 用 SF Symbols 的对应符号。

## 5. 四个关键屏：现状与已知问题

截图都在 `app/docs/`，手机 390 × 844，白天。

### 5.1 首页（地球）
- `r8_home_idle.jpg`（空闲）、`r8_home_traveling.jpg`（旅行中）、`r8_home_departing.jpg`（要出发）、`r8_home_night_idle.jpg`（夜）。
- 现状：左上字标，右上四个玻璃圆按钮，地球居中，地球上浮着书的标签，底部「新建旅程」和一张状态卡。
- 已知问题：地球外的天色与光晕偏蓝紫（8.1）；地球上书的标签（白底墨字）和界面的标签不是一套字号；状态卡与新建按钮的竖向距离没按 8 的倍数。

### 5.2 书（某一趟旅程的天列表 / 某一天）
- `r8_book.jpg`（天列表）、`r8_day_list.jpg`、`r8_book_todos.jpg`（某一天：序号、组图标、待办标签）。
- 已知问题：天列表每行信息偏多（D 标签 + 标题 + 日期 + 站数）；标题一长就省略，和 D 标签挤在一起；进入按钮与标题的对齐靠眼睛。

### 5.3 某一天（浮岛 + 底部抽屉）
- `r8_day_page.jpg`、`r8_day_page_todos.jpg`。
- 这一屏是仓库主人说「整体的信息排版还是太乱」最集中的地方。第八轮末已把它收成：标题行（D1 标题 + 日期 + 前一天 / 后一天）、「下一站」一行、和书里一样的行程列表、底部一排（编辑态开关 + 添加）。时间轴条、「行程」小标题、每行的「⋯」都去掉了。
- 还想要的：右上那一列四个控制（暂停 / 跟随 / 重播 / 小人）要不要收成更少；「下一站」那一行和列表第一行的关系怎么表达更清楚；编辑态（每行右边四个图标按钮）有没有更轻的做法。

### 5.4 站点详情
- `r8_stop_detail.jpg`：标题，一行类型标签与时间，一行怎么去，「待办」入口行，「添加备注」入口行，底部：删除（图标）、编辑（图标）、导航（文字）、打卡（主按钮）。
- 已知问题：底部四个按钮三种样式并排，可以更统一；类型标签那一行和时间的左右关系；导航弹出的四个地图 App 列表是否该直接用系统的分享面板样式。

## 6. 3D 建模部分

### 6.1 现状
- 风格：世界风 CG（视觉文档第 8 节定案）：圆润、低多边形、平涂为主、少量柔和阴影，像潮玩微缩。
- 小人：v4，一体圆润、毛线帽、晨色外套（`hero-*.ts`；`app/docs/hero_v3_sheet.jpg`、`r5_hero.jpg`、`r6_face.jpg`）。
- 名胜：六大洲各一批，程序化积木搭的（`landmark-kit.ts`：圆角盒、圆柱、圆锥、球、三棱柱、小屋、旗、山峰、水面、蒸汽）。规则：一座塔高 3～5 个单位、占地 1～2.5、比例夸张、边角圆润、**每个模型不超过 5 种颜色**。实验页：`hero-lab.html?lm=famous&region=asia|europe|americas|nordic|africa|oceania`。
- 截图：`r8_landmarks_asia.jpg`、`_europe`、`_americas`、`_nordic`、`_africa`、`_oceania`、`r5_landmarks.jpg`。
- 已知问题（视觉文档 15.4 / 观察 O20）：亚洲、欧洲、美洲三页尺度与配色基本一致；北欧第一批六个最粗（辛格韦德利、黑沙滩、钻石冰沙滩、Vigeland、阿美琳堡与玫瑰堡共用一个模板、新港与 Bryggen 共用一排房子），要重做。

### 6.2 请 Claude Design 给的
1. **风格板**：一张「地球Online 的名胜应该长什么样」的参考板——三到五个代表性名胜的正面 / 四分之三视角插画，统一的光（左上暖、右下冷）、统一的材质感（哑光平涂 + 一点点次表面感）、统一的边角圆润度。
2. **比例与配色表**：按六组（人文 / 自然 / 休闲 / 吃喝购物 / 交通 / 住宿）各给一个「体量块」（高、占地、主色、次色、点缀色），让程序化模型有尺可量。
3. **逐个批注**：对六张 `r8_landmarks_*.jpg`，每个模型一句话：留 / 调（调什么）/ 重做。
4. **小人与名胜的关系**：小人站在名胜旁时的尺度感（现在小人约 1.6 个单位高，名胜 3～5）。

Claude Design 给的是图与表，不是网格；我们拿着它改 `landmarks/*.ts` 里的参数。

## 7. 请回给我们什么

- 画板：首页（空闲 / 旅行中 / 要出发）、书、某一天、站点详情，各白天与夜里一张，390 × 844，iPhone 安全区。
- 每张画板旁一列「改了什么、为什么」，每条一句。
- 一张 Design System 页：色、字（只有两档）、间距、圆角、组件状态（默认 / 按下 / 禁用 / 焦点）。
- 第 6.2 节的四样。
- 不要：新的强调色、第三档字号、全大写、字间距、装饰性的编号、每张卡片一样的投影。

## 8. 开放问题

1. **去紫**：墨的色相（225°）、天空（长春花蓝 → 丁香）、地球光晕（`#857CD4`）三处一起改，才真正去得掉。想要的方向：墨改中性炭黑一族，白天的纸是暖白；天空用干净的天蓝到奶白；光晕白到淡天蓝；暮色橙到玫瑰；夜近黑的深蓝。晨色与新建旅程的暖色保留。请给两套候选并排。
2. 某一天右上那一列控制要不要减到两个。
3. 书的天列表每行到底留几样信息。
4. 鸿蒙版的视觉要不要和 iOS 完全一致，还是按鸿蒙的字体与圆角微调。
