## 2026-09-29 · 第一次讨论：产品立意

### 原始想法（仓库主人口述，按原意整理）

- 想做一个**游戏化的旅行攻略 App**。
- 平台：**先在鸿蒙端上架**，同时要有**苹果端**。
- 行程组织方式：按**整个旅程 → 天**来排行程，行程中可以**插入住宿和交通**。
- 看行程的方式：一个**像素画小人**，像《星露谷物语》那类游戏一样，在地图上**从第一站走到第二站**，第一天、第二天地走下去；用户在这个界面里看行程。
- 整体视觉：**像素画风格**。
- 行程配置这块可以**参考圆周旅记**（核实：该产品官方名称为「圆周旅迹 / Pi Travel」，见 `01_产品构想_v0.3.md` 第 9 节）。
- 每次打开一段旅程，要像**打开一本魔法书、进入另一个世界**；这个世界里的东西要**根据这趟旅行生成**，每本书不一样。
- 要能**导出旅行行程日记**。

讨论过程中追加的三点：

- **多考虑折叠屏场景**，点名华为 Pura X Max 与苹果 iPhone Duo。
- **双生态工程怎么做**：如果同时开发 Pura X Max 的应用和 iPhone Duo 的应用，鸿蒙和苹果两个生态，工程和开发细节怎么处理？
- **地图别手画**：看看有没有开源引擎能直接把地图渲染成像素的样子，后期要适配大量目的地。

### 本次讨论中形成的判断

| 编号 | 判断 | 说明 |
|---|---|---|
| D1 | 一份数据、两种视图 | 行程编辑用高效的列表/卡片视图（效率优先，参考圆周旅迹）；看行程用像素世界视图（沉浸优先）。不强迫用户在像素地图上做编辑。 |
| D2 | 「书」是顶层隐喻 | 书架 = 旅程列表；一本书 = 一段旅程；一页 = 一天；合上书 = 归档并生成日记。所有导航都顺着这个隐喻走。 |
| D3 | 交通是「边」，住宿是「归宿」 | 交通条目连接前后两个站点；住宿条目是一天的终点，连续多晚自动延续。这决定了数据结构和像素世界里的动画规则。 |
| D4 | 世界生成以规则为主、AI 为辅 | 地形/色板/建筑由「目的地 + 季节 + 主题」查表加固定随机种子生成，保证同一本书每次打开都一样；AI 只负责文字类内容（序言、每日标题、NPC 台词）。 |
| D5 | 像素地图不承担导航职责 | 真实导航交给系统地图（花瓣地图 / 高德 / Apple 地图）；像素地图只表达「顺序、关系、氛围」。 |
| D6 | 游戏化服务于记录感，不做留存钩子 | 有收集、成就、小人成长；不做排行榜、不做打卡惩罚。 |
| D7 | 开合手机 = 开合这本书 | 折叠机合上是一页（外屏），展开是跨页（左编辑右探索），半开悬停是把书立在桌上。Pura X Max 与 iPhone Duo 展开后都接近 √2:1，正是纸张比例。折叠屏是这个产品最合适的载体，P0 就做展开态双页。 |
| D8 | 双原生 UI，契约共享 | 鸿蒙 ArkUI、iOS SwiftUI 各写各的；共享的是数据规范、规则表、算法规格、素材和黄金用例，两端结果逐字节一致。鸿蒙先做，iOS 晚 4–6 周照冻结的契约做。 |
| D9 | 地图几何由真实地图数据生成，画法由规则自动完成 | 没有现成的「OSM → 像素游戏地图」引擎，但 OSM 取数、栅格化、LDtk 式自动铺 tile 规则、tilemap 格式各有成熟开源件；生成放服务端，客户端只渲染。 |

## 2026-09-29 · 第二轮（同日）：视角与积木

### 追加的想法（仓库主人口述，按原意整理）

- 视图**不一定一直是俯视图**，可以带一些角度，更像游戏里的视图。
- 用户的**关键点（站点）可以像乐高一样搭起来**。

### 本轮形成的判断

| 编号 | 判断 | 说明 |
|---|---|---|
| D10 | 像素化的 3D 微缩世界，视角有档位 | 正交相机，俯仰 26.6° / 90° 两档、方位四档；像素感靠 16×16 纹理加低分辨率渲染后最近邻放大。世界是 3D 的，画面仍是像素画。 |
| D11 | 站点 = 一栋积木建筑：系统先搭、用户可改、打卡封顶 | 底座来自 OSM 轮廓，模板按类别与主题选，用户在搭建模式里换色加装饰；未打卡的建筑缺顶，旅行结束整座城完成。编辑视图里的条目卡片也画成积木，两种视图共用隐喻。 |
| D12 | 世界层改为游戏引擎实现，两端共用一份代码 | 带角度的 3D、像素化后处理、体素合并与实例化、用户搭建编辑，合在一起超出自研 2D 渲染器的合理范围。首选 Cocos Creator 3.x（TypeScript，官方支持鸿蒙 NEXT 与 iOS）作为库嵌入原生页面；UI 层仍双原生。 |
| D13 | 与「乐高」保持距离 | 产品内不用乐高 / LEGO 字样，小人不做人仔造型，砖的凸点与比例用自己的设计；法务过一遍。 |
| D15 | 主视图是城市尺度，地标放大、街区只画肌理 | 看过街区尺度的示意图后指出：旅行攻略是城市维度，不能这么具象。改为一格约 100–300 米、一天一块底板放下整座城；地标按手绘旅游地图的做法放大到 2–4 格，普通街区只铺底板加零星小砖；山、河、路网、铁路是骨架。街区尺度不做主视图，单体尺度只用于点开站点与搭建。 |
| D16 | 像素小人：大头极简、图层换色、槽位刻意少 | 看过城市尺度图后说「有点这个感觉了」，要一个类似极简像素小人气质的角色，用户可自定义，在路线上走。定为 16 × 20 px 的面向相机精灵，两点眼加腮红，部件为可换色图层；P0 槽位：肤色 5、发型 4 × 发色 7、上衣下装鞋只换色、帽子 3 款、配件 4；新款通过旅行解锁。不复制任何现有 IP 的造型。 |
| D14 | 带角度好，但只能是固定的辅助角度 | 追问「这样显示好不好」的答案：主视角定为 2:1 二等角（俯仰 26.6°、方位 45°，像素等距游戏的标准角），旋转只给 4 方位档 + 正俯视档，不给连续旋转；人物用像素精灵，建筑用体素积木（HD-2D 配方）。原型阶段与 3/4 俯视并排对照后定案。参考游戏与规律见产品构想附录 A。 |

### 待定事项（带回下次讨论）

## 2026-09-29 · 第三轮（同日）：七天行程

### 追加的要求

- 尝试做一个 7 天的行程看看效果。

### 做了什么

- 定了一段真实可走的**关西七日**：大阪抵达 → 大阪城与塔 → 京都东山 → 京都洛西 → 奈良一日往返 → 神户港与山手 → 大阪返程。23 个站点、25 段交通、3 家住宿。
- 地图渲染器改成数据驱动（`示意图/render_trip_book.py`）：一个场景 = 地面网格 + 路网 / 铁路 / 地铁 + 地标列表；新增大阪、奈良、神户三座城和十几个地标模板（机场、大阪城天守、梅田双塔、通天阁、道顿堀招牌、东大寺大佛殿、春日大社、异人馆、南京町牌坊、港塔、船、酒店）。
- 出图 `示意图/关西七日_一本书.png`：封面 + 七页，每页一块城市底板、当天路线、站点旗与住宿旗、页脚站点与交通列表。
- 行程数据落成 `示例数据/关西七日.json`（schemaVersion 0.1，按产品构想 8.2 的模型）。

### 看图后的观察

| 编号 | 观察 | 说明 |
|---|---|---|
| O1 | 「一页一天」在七天下成立 | 七页并排就是一本书的目录，每页自成一景又互相呼应（同一座城的两页共用底板，只换路线）。 |
| O2 | 同城多日要复用底板 | 大阪三页、京都两页共用同一块底板，只换路线和小人位置；底板生成一次缓存即可，印证地图方案第 7 节的缓存策略。 |
| O3 | 跨城的一天靠交通条目衔接 | 第 3 天从大阪到京都、第 5 天奈良往返，页面只画目的城；城际交通在页脚和翻页过场里表达，不画在底板上。 |
